# 어드민 프로젝트 관리 기획

사피어 내부에서 프로젝트 진행을 관리하는 웹 어드민(`/admin`)과, 그 내용을 고객 포털(`/dashboard`)로 공유하는 흐름을 정리한다.

## 목적

- 프로젝트 진행(일정·작업·보고·회의록·요청)을 한곳에서 관리한다.
- 고객에게 보낼 내용은 어드민에 이미 입력한 데이터에서 만든다. 같은 내용을 메일·메신저로 다시 쓰지 않는다.
- 고객은 로그인한 포털에서만 본다. 공유 링크는 만들지 않는다.

## 누가 쓰나

| 역할             | 화면         | 하는 일                                                |
| ---------------- | ------------ | ------------------------------------------------------ |
| 사피어 PM·실무자 | `/admin`     | 일정·작업 관리, 주간 보고 작성·공유, 회의록, 요청 처리 |
| 고객 담당자      | `/dashboard` | 진행 현황·보고·회의록 확인, 요청 보내기                |

내부 계정은 세션의 `staff: true`로 구분한다. 데모 계정은 `staff@demo.saffir.co.kr`이고, 로그인하면 `/admin`으로 간다.

## 자동 계산

- **진행률**: 전체 마일스톤 중 완료 비율. 앞으로의 단계까지 포함한 전체 일정 기준이라 작업 수보다 고객에게 설명하기 쉽다.
- **상태**
  - 지연: 예정일이 지난 미완료 마일스톤이 있음
  - 주의: 마감이 지난 작업 또는 보류 작업이 있음
  - 정상: 그 외
  - 이유를 프로젝트 상단에 같이 보여 준다.
- **주간 보고 초안**: 고객 공개 작업만 쓴다.
  - 한 일: 그 주에 완료한 작업과 마일스톤
  - 다음 할 일: 다음 주 일요일까지 마감인 미완료 작업
  - 이슈: 보류 작업, 마감이 지난 작업
  - 고객 확인 요청: 승인 대기 산출물
  - PM은 초안을 고친 뒤 저장하거나 공유한다.

## 고객에게 공유되는 것

| 항목                             | 공유 기준                                                 | 포털 위치                                        |
| -------------------------------- | --------------------------------------------------------- | ------------------------------------------------ |
| 단계·진행률·다음 일정            | 항상                                                      | 홈, 프로젝트                                     |
| 마일스톤                         | '고객 공개' 표시한 것 (예정일을 바꾸면 알림)              | 프로젝트 › 단계별 일정                           |
| 산출물                           | '작성 중' 이후 모두. 승인 요청한 것은 승인·수정 요청 버튼 | 프로젝트 › 산출물 확인·승인, 홈 › 지금 처리할 일 |
| 작업                             | '고객 공개' + 미완료                                      | 프로젝트 › 진행 중인 작업                        |
| 주간 보고                        | '공유하기' 누른 것                                        | 작업 보고                                        |
| 회의록                           | '공유하기' 누른 것                                        | 작업 보고 › 정례 미팅 기록                       |
| 요청 답변·상태                   | 항상                                                      | 요청·문의                                        |
| 내부 메모, 담당자 배정, 우선순위 | 공유 안 함                                                | -                                                |

공유·마일스톤 완료·요청 답변·상태 변경은 고객 포털 홈 '최근 알림'에 남는다. 메일·알림톡 발송은 다음 단계에서 붙인다.

## 고객 → 어드민

고객이 포털 '요청·문의'에서 요청을 보내면 어드민 요청함에 `접수` 상태로 들어온다.

- 유형: 수정 요청, 장애 신고, 문의
- 장애 신고는 우선순위 '긴급'으로 자동 지정한다.

## 데이터 구조 (`src/server/projects`)

- `types.ts`: PmClient, PmProject, Milestone, Task, Report, Meeting, PmRequest
- `store.ts`: 읽기·계산·쓰기 함수. 지금은 서버 메모리라 서버를 다시 켜면 `seed.ts`로 돌아간다.
- `server/portal`의 `requirePortal`이 이 저장소에서 고객사 공개 항목만 꺼내 포털 데이터에 넣는다.
- 어드민 저장은 `features/admin/api/actions.ts` (서버 액션, 모두 `requireStaff` 확인).

## 다음 단계

1. 사이트 DB 연결: `store.ts` 함수 안쪽만 DB 조회·저장으로 바꾼다.
2. 내부 계정 관리: 실제 직원 계정, 권한(PM / 실무자).
3. 프로젝트 등록을 계약·청구(포털 청구)와 연결: 계약금 결제 → 프로젝트 자동 생성.
4. 고객 포털 초대: 설정 탭에서 고객 담당자 초대 메일.
5. 알림 발송: 보고 공유·요청 답변을 메일/알림톡으로.
6. 파일 첨부: 요청·산출물에 첨부.
